# Project continuity in the Brain

Maintain a concise conversational state even when no file is authorized. When the user
has asked to keep the project context in the Brain, use that existing authorization
for the agreed scope. Otherwise ask once before the first durable project write;
do not repeatedly ask during already authorized note maintenance.

Delegate locating the existing project note, its index entry, and the applicable
vault instructions. Prefer updating the canonical note over creating a second source
of truth. The main agent owns the authorized write after reading the returned
instructions. Keep artifacts and task tracking in the locations required by the
workspace. Do not create tasks merely because a business conversation began.

Keep notes short. Record the user's statements with their date, evidence with its source,
and decisions he has actually accepted. Do not persist speculative proposals unless
requested. When proposals are requested, label them separately from decisions.
Do not overwrite old evidence to make the new conclusion appear inevitable.

Use only the fields relevant to the session:

- Identify the project and the current question.
- State the customer outcome and distinguish buyer and user if needed.
- Summarize known facts and their sources.
- List the critical hypotheses that remain open.
- Record the accepted decision, its reason, and what would reopen it.
- Preserve an experiment's original criterion and any later change with its date.
- State the next action, its owner if agreed, and what is needed to resume.

An experiment result should distinguish the original expectation, actual observation,
interpretation, limitations, and ensuing decision. Link to raw evidence instead of
pasting entire transcripts. Update the vault index when its conventions require it.
Confirm writes only after checking the saved file. Never claim that a project note
updated the agent's separate memory system, a cloud chat, or another inaccessible vault.
